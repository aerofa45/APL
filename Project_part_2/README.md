# Emerald Lexer

## Description

This project implements a lexer for the Emerald programming
language designed in Part 1 of the final project.

The lexer converts Emerald source code into a sequence of tokens.
It recognizes keywords, identifiers, integers, decimal numbers,
operators, delimiters, whitespace, comments, arrays, and invalid
characters.

## Requirements

- Python 3.10 or later
- No external packages are required

## Running the Lexer

From the project directory, run:

python lexer.py test_inputs/test1_declaration.em

Replace the filename with any Emerald source file.

## Running the Tests

Run:

python -m unittest test_lexer.py -v

## Files

- token_definitions.py: Token types and Token class
- lexer.py: Lexer implementation
- test_lexer.py: Automated unit tests
- test_inputs/: Emerald test programs
- outputs/: Saved output for every test
- UPDATED_GRAMMAR.md: Updated lexical grammar
- AI_USE_STATEMENT.md: Explanation of AI assistance

## Error Handling

When the lexer encounters an unsupported character, it raises a
LexerError containing the invalid character and its source
location.

Example:

Lexical error at line 1, column 12:
invalid character '@'


## Design and verification

The scanner advances through source characters and records each lexeme's
starting line and column. Token categories are separate from source spelling.
See UPDATED_GRAMMAR.md for exact character rules and corrections to Part 1.
The existing parent-folder Lexical.cpp is a separate C++ example; this
submission follows the requested Python project structure.

The six example files cover declarations, arithmetic, printing, control flow,
an intentional lexical error, and functions/arrays. Additional automated
tests cover all keywords and operators, for loops, booleans, comments,
positions, malformed decimals, ASCII restrictions, EOF, and CLI errors.
The lexer recognizes tokens; it does not execute the example programs.

Run all tests from this folder:

```sh
python -m unittest discover -v
```

Saved outputs were generated by running the CLI on each input. Test 5 exits
with status 1 intentionally; the other five exit with status 0. The invalid
character is at column 12. CLI usage, file reading, and lexical errors produce
status 1 and a readable message; successful scans produce status 0.

To regenerate example outputs portably:

```sh
python generate_outputs.py
```

Only Python's standard library is required.
